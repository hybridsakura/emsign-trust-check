emSign Trust Check

Does your browser still trust the compromised eMudhra intermediate CAs? — a self-hostable, intranet-friendly checker inspired by emudhra.we-have-a-problem.comthe public eMudhra disclosure

Background

On 17 October 2026, the private keys of eight eMudhra intermediate CA certificates were confirmed compromised (recoverable from the certificates themselves). They chain to roots trusted by the Mozilla, Microsoft, Apple and Chrome root programs. An attacker holding these keys can impersonate any website.

The certificates have been blocked in Firefox and Chrome since Oct 17, on Apple platforms since Oct 19, and on Microsoft platforms since Oct 20 — delivered through revocation push mechanisms (CRLite, CRLSets, Disallowed CTL). Machines that stay offline for long periods (typical intranet computers) may never have received these pushes and need to be checked individually.

Live check requires access to the external test domains

This page opens HTTPS connections to twelve test sites whose certificate chains are signed by the compromised intermediates. If a connection succeeds, your browser still trusts that chain and is at risk. If it is rejected by certificate validation, you are protected.

If every row above shows a timeout, this machine cannot reach the test domains and the live check is inconclusive. Use the bundled offline checker instead:

This is the LAN edition: it makes no outbound network requests. Run the bundled checker on the machine you want to inspect — both scripts read the local trust store and installed browser versions only.

  • Check-EmSignTrust.ps1 — Windows PowerShell script that compares the 16 compromised certificates' fingerprints against the local Disallowed CTL, enumerates installed browser versions.
  • check-emsign-linux.sh — Linux equivalent: inspects distrust markers in the local trust store and the ca-certificates package version.
  • block-emsign-certs.ps1 — remediation for machines that cannot install Windows updates: imports the 16 certificates into the local Disallowed store offline (works without WSUS or a patch pipeline; -Remove rolls back, -Status reports the current state).
  • fingerprints.json — SHA-1/SHA-256 fingerprints of all 16 compromised certificates (computed locally from PEM, SHA-256 verified against the official list).
  • impacted-intermediates.json — the official certificate data (with PEM) for offline chain verification with OpenSSL.

Remediation

  • Windows / Edge / Chrome: install the latest cumulative updates (Microsoft pushed the disallowed-list block from Oct 20) and update browsers.
  • Firefox: update to the latest version (CRLite/OneCRL deliver the block automatically).
  • macOS: install the security updates released after Oct 19; note that bundled curl/git/python3 verify against /etc/ssl/cert.pem which needs separate handling.
  • Dev toolchains: NSS ≥ 3.131.1, certifi ≥ 2026.10.19, Node.js ≥ 22.23.4, Go ≥ 1.26.10, curl CA bundle ≥ 2026-10-20 (full list on the original site).
  • After checking, export or screenshot the result and hand it to your security administrator.
